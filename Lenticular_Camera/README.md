# 低一点，看见另一面 / 双图视角实验

项目已从交错图光栅模拟改为 **普通墙图识别 + 双图视角切换**。保留文件夹名 `Lenticular_Camera`，不再需要交错图片、LPI、帧数或实际打印尺寸。

## 体验

- 图片 A：与墙上张贴的图片一致，用作视觉识别目标。
- 图片 B：从低处仰视时出现的另一张图片。
- 成年人站立、正对墙图：手机只显示真实摄像头画面，B 隐藏。
- 手机随身体降低并仰视墙图：B 覆盖在识别到的墙图位置，跟随位置、大小及透视变化。
- 回到站立位置：恢复真实画面。墙图识别丢失：隐藏 B。

手机独立运行，使用时无需电脑连接。图片由手机选择，在本地编译识别特征与处理摄像头视频，不发送给服务器。刷新页面后需重新选择两张图。

## 使用步骤

1. 将 A 打印并平整贴在竖直墙面上，顶部朝上。选用细节丰富、对比清晰、非重复纹理的普通图片，避免反光、折皱和纯色图。
2. 手机打开 HTTPS 网页，分别上传 A 的原图和 B。建议两张图比例一致；不一致时 B 居中裁切以填满 A 的区域。
3. 点击「打开摄像头并识别墙图」，允许摄像头权限。首次启动需联网加载识别引擎，然后在手机内分析 A，进度显示在页面中。处理速度取决于手机性能。
4. 成年人站立、将手机保持在正常观看高度，正对墙图。看到「已识别 A」且校准按钮可用后，点击「记录站立视角」。未完成此步骤时，B 不会出现。
5. 蹲下，将手机随身体降到儿童观看高度，同时继续对准墙图；等识别稳定后点击「记录蹲下视角」。系统根据两个位置的角度差自动设置触发阈值。也可直接用默认 12° 阈值试验。
6. 站起、蹲下反复体验。必要时调整「触发仰角」，或重新记录站立与蹲下视角。

需要让完整墙图持续留在镜头里；太远、太近、极斜角度或遮挡都可能导致识别失败。按「关闭摄像头」立即结束识别；页面进入后台时也会关闭相机，返回后需重新开始并校准。

「不打开摄像头，先测试两张图」提供明确标注的手动测试，不执行墙图识别，不代表真实 AR 已验证。

## 视角判定

使用 MindAR 识别 A 并估计平面相对相机的姿态。将相机位置转换到图片坐标，计算相机低于图片中心时的仰角，再减去站立校准值。单纯在同一位置转动手机不会改变理想几何中的相对观看位置。

这是相机相对图片位置的估计，**不检测人的年龄、身体或是否真的蹲下**。站着把手机降低也会触发；蹲下但把手机留在原高度不会触发。角度不是专业测量值，可能受镜头参数、识别误差影响。墙图应平整、竖直、正向张贴，校准需要在实际布置现场完成。

画面随仰角连续混合，不再在阈值处突然切换。默认过渡中心为 12°、范围为 12°：约 6° 开始显现，12° 时混合一半，18° 完全显现；站起时按相同曲线反向淡出。可调「过渡角度范围」，范围越大变化越缓慢。站立位置保持透明。

透明度使用平滑曲线和按时间计算的缓动，避免手机帧率不同造成动画速度变化。图片四角进行自适应平滑：抑制细小抖动，快速移动时加快跟随。边缘约 0.65% 范围轻微柔化，减弱生硬的矩形覆盖边界；校准后隐藏画面内操作提示。

丢失目标时在最后可信位置快速淡出，最多保留 150 ms；超过 500 ms 未收到位姿更新也视为丢失。重新识别从透明开始，避免把上一位置的图片拖到新位置。关闭摄像头或重新记录站立视角立即清空覆盖。覆盖通过图片四角的投影和 CSS 透视变换完成。

无缝程度仍取决于图片内容和现场光线：A 与 B 使用相同构图、比例、边缘与接近的亮度会更自然。当前是透视贴合与透明度混合，不包含图像形变生成、自动光照匹配或人物遮挡分割。

## 发布到手机可访问的网站

将以下文件放在同一 HTTPS 静态网站目录：

```text
index.html
style.css
app.js
core.js
ar.html
ar.js
```

`ar.html` 是同源识别运行窗口，父页面授予它摄像头访问权限。托管站点不能禁止同源 iframe 或摄像头。识别引擎通过固定版本的 jsDelivr 地址加载，需允许其 ESM 模块及 Blob Worker；如站点配置 CSP，应按实际依赖配置，不应一律禁用安全策略。

当前代码本身不产生在线网址。发布后手机访问 HTTPS 链接即可，正式使用无需电脑开机。直接打开 HTML 文件或使用局域网 HTTP 地址通常无法调用手机摄像头。

## 本地开发（可选）

```powershell
cd D:\IMA-Creative-Computing\Lenticular_Camera
node serve.cjs
```

电脑访问 http://localhost:3010。手机正式使用 HTTPS 托管地址。本地服务器也支持可信证书：设置 `TLS_CERT` 与 `TLS_KEY` 环境变量，再启动服务器；证书需受手机信任且与访问域名匹配。

## 实现与验证

- `app.js`：双图选择、缩图、权限入口、状态、校准和手动测试。
- `ar.js` / `ar.html`：隔离的识别会话，负责摄像头、目标编译、跟踪与透视覆盖；结束会话时移除运行窗口，释放其资源。
- `core.js`：角度几何、透视矩阵和切换状态。
- A 工作图最长边 1000 px，B 最长边 1800 px；仅用于手机性能优化，不修改上传原文件。纯色及特征太少的目标会提示更换图片。
- `node core.test.cjs`：验证站立／蹲下角度、相机原地旋转不触发、投影与裁切、四角透视映射、稳定等待、回差及丢失目标处理。

目前几何与状态测试可自动运行，真实手机相机、实际墙图识别率、移动浏览器性能与 AR 贴合效果仍需现场实测。项目使用网络加载的 [MindAR 1.2.5](https://github.com/hiukim/mind-ar-js/tree/v1.2.5)（MIT）；接口参考其 [Controller](https://github.com/hiukim/mind-ar-js/blob/v1.2.5/src/image-target/controller.js) 与 [Compiler](https://github.com/hiukim/mind-ar-js/blob/v1.2.5/src/image-target/compiler.js)。
